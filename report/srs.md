## 1. Введение

Документ описывает требования к веб-приложению «Retro SFX Lab» — генератору ретро-звуков (прыжки, монеты, взрывы, лазеры) для инди-игр. Звук синтезируется из параметров (форма волны, огибающая, скольжение частоты, фильтры) и сохраняется в файл WAV.

### 1.1 Назначение документа

SRS определяет, **что** должно делать приложение, а не **как** оно будет реализовано. Заказчик использует документ, чтобы подтвердить границы продукта и критерии приёмки; разработчик — как основу для проектирования, реализации и тестов. Уникальные идентификаторы позволяют связывать требования с моделями и проверками.

### 1.2 Область применения продукта

**Продукт:** «Retro SFX Lab», версия 0.1, одностраничное веб-приложение (SPA), работающее целиком в браузере.

**Назначение.** Разработчик игры выбирает готовый пресет (прыжок, монета, взрыв и т. д.) или создаёт звук с нуля, настраивает параметры ползунками, сразу слышит результат и экспортирует его в WAV для использования в игре.

**Бизнес-цели (источник: Заказчик):**

| ID | Бизнес-цель | Измеримый результат |
|----|-------------|---------------------|
| BO-1 | Разработчик быстро получает звук для прототипа игры | Звук из пресета создаётся и экспортируется не более чем за 3 действия |
| BO-2 | Звук можно тонко настроить без знаний цифровой обработки сигналов | Каждый параметр имеет понятное название, диапазон и мгновенно слышимый эффект |
| BO-3 | Результат пригоден для игровых движков | Файл WAV (16 бит, PCM) открывается в Unity, Godot и аудиоредакторах |
| BO-4 | Удачные звуки можно сохранить и воспроизвести повторно | Один и тот же набор параметров даёт одинаковый WAV-файл |
| BO-5 | Набор звуков проекта получается разнообразным | Кнопки случайной генерации и мутации создают вариации одного звука |

**Входит в область:** синтез звука по параметрам, пресеты, случайная генерация и мутация, воспроизведение, визуализация формы волны, история изменений, экспорт в WAV, сохранение и загрузка параметров в JSON.

**Не входит в область:** запись с микрофона, импорт и редактирование чужих аудиофайлов, многодорожечный секвенсор, музыкальная композиция, экспорт в MP3/OGG, облачное хранилище и учётные записи, мобильные приложения.

### 1.3 Определения, акронимы и сокращения

| Term | Definition |
|------|------------|
| 8-bit / чиптюн | Стиль звука игровых приставок 1980-х с простыми формами волны |
| ADSR | Attack, Decay, Sustain, Release — огибающая громкости: нарастание, спад, удержание, затухание |
| Bitcrush | Эффект уменьшения разрядности отсчётов, создающий «грязный» цифровой звук |
| Duty cycle (скважность) | Доля периода прямоугольной волны, в течение которой сигнал высокий |
| PCM | Pulse-Code Modulation — несжатое представление звука отсчётами |
| SPA | Single Page Application — одностраничное веб-приложение |
| SRS | Software Requirements Specification — спецификация требований к ПО |
| Seed | Начальное число генератора случайных чисел; определяет воспроизводимость случайных вариаций |
| Slide | Плавное изменение частоты звука во времени |
| SysML v2 | Systems Modeling Language версии 2 — язык моделирования для графической части |
| TBD | To Be Determined — значение ещё не согласовано с Заказчиком |
| UI | User Interface — пользовательский интерфейс |
| WAV | Контейнерный формат звукового файла (RIFF/WAVE) |
| Web Audio API | Браузерный интерфейс для воспроизведения и обработки звука |
| Арпеджио | Резкая смена высоты звука через равные интервалы времени |
| Вибрато | Периодическое колебание частоты звука |
| Пресет | Готовый набор параметров, соответствующий типовому игровому звуку |
| Частота дискретизации | Количество отсчётов звука в секунду (Гц) |

## 2. Обзор продукта

### 2.1 Перспектива продукта

Приложение автономно: серверной части нет, параметры и звуки не покидают компьютер пользователя. Ядро синтеза — чистые функции, формирующие массив отсчётов по набору параметров. Воспроизведение выполняется через Web Audio API, экспорт — сборкой файла WAV из того же массива отсчётов, поэтому прослушанное и сохранённое совпадают.

### 2.2 Функции продукта

- синтез звука: формы волны, скважность, частота, огибающая ADSR, скольжение, вибрато, арпеджио;
- фильтры низких и высоких частот, эффекты bitcrush и снижения частоты дискретизации;
- пресеты, случайная генерация и мутация параметров;
- воспроизведение и визуализация формы волны;
- история изменений параметров;
- экспорт в WAV, сохранение и загрузка параметров в JSON.

### 2.3 Ограничения продукта

- Язык разработки — TypeScript (strict), звук — Web Audio API, сборка — Vite.
- Серверной части нет; внешние сервисы и платные библиотеки не используются.
- Поддерживаются актуальные версии Chrome, Firefox и Edge.
- Длительность звука не более 5 секунд; моно, 44100 Гц по умолчанию.
- Приложение формирует только синтезированные звуки и не обрабатывает чужие аудиофайлы.

### 2.4 Характеристики пользователей

| Роль | Описание | Навыки и ожидания |
|------|----------|-------------------|
| Разработчик игры | Создаёт звуки для своего проекта | Не обязательно знает синтез звука; ожидает пресеты и мгновенный отклик |
| Дизайнер звука | Тонко настраивает звук и сохраняет наборы параметров | Понимает ADSR и фильтры; ожидает точные значения и воспроизводимость |
| Разработчик приложения | Дорабатывает и сопровождает приложение | Знает TypeScript; ожидает независимое ядро и тесты |

### 2.5 Допущения и зависимости

- Пользователь работает в браузере с поддержкой Web Audio API и имеет рабочее звуковое устройство.
- Воспроизведение звука начинается после первого действия пользователя (требование политики автозапуска браузеров).
- Размер звука ограничен 5 секундами, поэтому весь звук помещается в оперативную память.
- Игровые движки Заказчика принимают WAV 16 бит PCM.

**REQ-INT-001 — Поддерживаемые браузеры**
- **Statement:** Приложение должно запускаться и работать в актуальных версиях Chrome, Firefox и Edge.
- **Rationale:** Заказчики используют разные браузеры.
- **Acceptance Criteria:** Сценарии C-1…C-6 выполняются в трёх браузерах без ошибок в консоли.
- **Verification Method:** Demonstration

**REQ-INT-002 — Автономная работа**
- **Statement:** Приложение должно работать без серверной части и подключения к сети после загрузки статических файлов.
- **Rationale:** Работа без интернета.
- **Acceptance Criteria:** При отключённой сети доступны все функции раздела 3.2.
- **Verification Method:** Test

**REQ-INT-003 — Отсутствие Web Audio API**
- **Statement:** Если браузер не поддерживает Web Audio API, приложение должно сообщить об этом и сохранить доступными экспорт WAV и сохранение параметров.
- **Rationale:** Экспорт не зависит от воспроизведения.
- **Acceptance Criteria:** При отключённой поддержке воспроизведения кнопка Play неактивна, экспорт работает.
- **Verification Method:** Test

**REQ-INT-004 — Управление с клавиатуры**
- **Statement:** Приложение должно поддерживать клавиши: Пробел — воспроизвести, R — случайный звук, M — мутация, Ctrl+Z / Ctrl+Y — история, Ctrl+E — экспорт.
- **Rationale:** Быстрый подбор звука.
- **Acceptance Criteria:** Каждая клавиша вызывает действие; в полях ввода клавиши не срабатывают.
- **Verification Method:** Test

**REQ-INT-005 — Русский интерфейс**
- **Statement:** Подписи интерфейса и сообщения должны быть на русском языке.
- **Rationale:** Язык Заказчика.
- **Acceptance Criteria:** В интерфейсе нет подписей на других языках, кроме названий форм волны и терминов ADSR.
- **Verification Method:** Inspection

**REQ-INT-006 — Размер экрана**
- **Statement:** Интерфейс должен корректно отображаться при ширине окна от 1024 px.
- **Rationale:** Работа на ноутбуках и мониторах.
- **Acceptance Criteria:** Все органы управления доступны без горизонтальной прокрутки.
- **Verification Method:** Demonstration

### 3.2 Функциональные требования

**REQ-FUNC-001 — Формы волны**
- **Statement:** Система должна синтезировать звук с формой волны: прямоугольная, пилообразная, треугольная, синусоидальная, шум.
- **Rationale:** Базовые тембры чиптюна (C-2).
- **Acceptance Criteria:** Для каждой формы волны спектр и график соответствуют ожидаемой форме.
- **Verification Method:** Test

**REQ-FUNC-002 — Скважность**
- **Statement:** Система должна позволять задать скважность прямоугольной волны от 5 до 95 %.
- **Rationale:** Изменение тембра «ширины» импульса.
- **Acceptance Criteria:** При скважности 50 % доли высокого и низкого уровней равны; другие значения меняют долю.
- **Verification Method:** Test

**REQ-FUNC-003 — Базовая частота**
- **Statement:** Система должна позволять задать начальную частоту от 20 до 8000 Гц.
- **Rationale:** Высота звука.
- **Acceptance Criteria:** Измеренная частота первого периода равна заданной с погрешностью не более 1 %.
- **Verification Method:** Test

**REQ-FUNC-004 — Огибающая ADSR**
- **Statement:** Система должна применять огибающую громкости ADSR: attack, decay (по 0–2 с), уровень sustain (0–100 %), время удержания (0–2 с) и release (0–2 с); общая длительность не должна превышать 5 с.
- **Rationale:** Форма звука «удар», «писк», «взрыв».
- **Acceptance Criteria:** Амплитуда по времени соответствует заданной огибающей; сумма параметров > 5 с ограничивается.
- **Verification Method:** Test

**REQ-FUNC-005 — Скольжение частоты**
- **Statement:** Система должна позволять задать скольжение частоты (−1…+1 октавы в секунду) и ускорение скольжения.
- **Rationale:** Прыжки, лазеры, падения.
- **Acceptance Criteria:** При положительном скольжении частота растёт, при отрицательном падает; значение 0 даёт постоянную частоту.
- **Verification Method:** Test

**REQ-FUNC-006 — Вибрато**
- **Statement:** Система должна позволять задать глубину (0–100 %) и частоту (0,1–20 Гц) вибрато.
- **Rationale:** Эффект «дрожащего» звука.
- **Acceptance Criteria:** При включении вибрато частота периодически отклоняется от базовой; при нулевой глубине вибрато нет.
- **Verification Method:** Test

**REQ-FUNC-007 — Арпеджио**
- **Statement:** Система должна позволять задать смещение частоты (−24…+24 полутона) и скорость смены, по истечении которой высота звука изменяется один раз.
- **Rationale:** Эффект монеты и бонуса.
- **Acceptance Criteria:** В момент смены частота изменяется скачком на заданное число полутонов.
- **Verification Method:** Test

**REQ-FUNC-008 — Фильтры**
- **Statement:** Система должна применять фильтры низких и высоких частот с частотой среза 20–20000 Гц.
- **Rationale:** Смягчение и «осветление» звука.
- **Acceptance Criteria:** При срезе 500 Гц ФНЧ ослабляет гармоники выше 500 Гц не менее чем на 12 дБ.
- **Verification Method:** Test

**REQ-FUNC-009 — Bitcrush и децимация**
- **Statement:** Система должна позволять снижать разрядность (1–16 бит) и частоту дискретизации эффекта (1000–44100 Гц).
- **Rationale:** Характерный «цифровой» звук.
- **Acceptance Criteria:** При 4 битах отсчёты принимают не более 16 уровней; при низкой частоте видны «ступеньки».
- **Verification Method:** Test

**REQ-FUNC-010 — Громкость**
- **Statement:** Система должна позволять задать общую громкость 0–100 % (по умолчанию 50 %).
- **Rationale:** Защита слуха и единый уровень.
- **Acceptance Criteria:** Пиковое значение отсчётов пропорционально выбранной громкости.
- **Verification Method:** Test

**REQ-FUNC-011 — Пресеты**
- **Statement:** Система должна содержать не менее 8 пресетов: прыжок, монета, взрыв, лазер, усиление, удар, блип, падение; выбор пресета заполняет все параметры.
- **Rationale:** Быстрый старт (BO-1).
- **Acceptance Criteria:** После выбора каждого пресета параметры соответствуют его описанию, звук воспроизводится.
- **Verification Method:** Test

**REQ-FUNC-012 — Вариации пресета**
- **Statement:** Система должна создавать вариацию пресета по seed: параметры отклоняются от базовых не более чем на ±15 %.
- **Rationale:** Разнообразие звуков одного типа.
- **Acceptance Criteria:** Разные seed дают разные звуки, один seed — одинаковый.
- **Verification Method:** Test

**REQ-FUNC-013 — Случайная генерация**
- **Statement:** Система должна создавать случайный набор параметров в допустимых диапазонах одной кнопкой.
- **Rationale:** Поиск неожиданных звуков (BO-5).
- **Acceptance Criteria:** Для 1000 запусков ни один параметр не выходит за диапазон.
- **Verification Method:** Test

**REQ-FUNC-014 — Мутация**
- **Statement:** Система должна изменять каждый параметр текущего звука на случайную величину не более ±10 % диапазона.
- **Rationale:** Тонкая вариация удачного звука.
- **Acceptance Criteria:** После мутации все параметры в допустимых диапазонах и отличаются от исходных.
- **Verification Method:** Test

**REQ-FUNC-015 — Воспроизведение**
- **Statement:** Система должна воспроизводить звук кнопкой «Play» и по клавише Пробел; повторное нажатие перезапускает звук.
- **Rationale:** Быстрая проверка результата.
- **Acceptance Criteria:** Звук начинается не позднее чем через 100 мс; два нажатия подряд не создают наложения.
- **Verification Method:** Test

**REQ-FUNC-016 — Визуализация**
- **Statement:** Система должна отображать форму волны всего звука на графике и обновлять её при изменении параметров.
- **Rationale:** Наглядность влияния параметров.
- **Acceptance Criteria:** После изменения любого параметра график обновляется.
- **Verification Method:** Test

**REQ-FUNC-017 — Экспорт WAV**
- **Statement:** Система должна экспортировать звук в файл WAV (PCM, моно, 16 бит) с частотой 11025, 22050 или 44100 Гц на выбор.
- **Rationale:** Использование в игровых движках (BO-3).
- **Acceptance Criteria:** Файл открывается в стороннем аудиоредакторе, заголовок и длительность соответствуют параметрам.
- **Verification Method:** Test

**REQ-FUNC-018 — Имя файла**
- **Statement:** Система должна предлагать имя файла по названию пресета и номеру вариации; недопустимые символы заменяются подчёркиванием.
- **Rationale:** Удобство и совместимость с ОС.
- **Acceptance Criteria:** Для пресета «Прыжок/1» предлагается `Прыжок_1.wav`.
- **Verification Method:** Test

**REQ-FUNC-019 — Сохранение параметров**
- **Statement:** Система должна сохранять текущие параметры в файл JSON.
- **Rationale:** Повторное использование звуков (C-5).
- **Acceptance Criteria:** Файл создаётся по команде и содержит все параметры и версию схемы.
- **Verification Method:** Test

**REQ-FUNC-020 — Загрузка параметров**
- **Statement:** Система должна загружать параметры из JSON, проверяя структуру, версию и диапазоны значений; при ошибке текущие параметры не меняются.
- **Rationale:** Файлы могут быть повреждены.
- **Acceptance Criteria:** Корректный файл восстанавливает звук; для некорректного — выводится сообщение.
- **Verification Method:** Test

**REQ-FUNC-021 — Воспроизводимость**
- **Statement:** При одинаковых параметрах и seed система должна создавать побайтно идентичные файлы WAV.
- **Rationale:** Повторяемость результата (BO-4).
- **Acceptance Criteria:** Два экспорта подряд дают файлы с одинаковой контрольной суммой SHA-256.
- **Verification Method:** Test

**REQ-FUNC-022 — История**
- **Statement:** Система должна хранить до 20 последних состояний параметров и позволять возвращаться к ним (отмена и повтор).
- **Rationale:** Возврат к удачному варианту.
- **Acceptance Criteria:** Ctrl+Z возвращает предыдущее состояние, Ctrl+Y повторяет изменение.
- **Verification Method:** Test

**REQ-FUNC-023 — Защита от перегрузки**
- **Statement:** Система должна ограничивать пиковое значение звука до 0 dBFS без выхода за границы 16 бит.
- **Rationale:** Отсутствие искажений и щелчков при переполнении.
- **Acceptance Criteria:** В экспортированном файле нет значений, вышедших за диапазон; при максимальных параметрах нет переполнения.
- **Verification Method:** Test

### 3.3 Качество обслуживания

#### 3.3.1 Производительность

**REQ-PERF-001 — Скорость синтеза**
- **Statement:** Синтез звука длительностью 1 секунда должен занимать не более 100 мс.
- **Rationale:** Мгновенный отклик при подборе параметров.
- **Acceptance Criteria:** Время расчёта для 1 с звука не превышает 100 мс на ноутбуке среднего уровня.
- **Verification Method:** Test

**REQ-PERF-002 — Отклик интерфейса**
- **Statement:** После изменения параметра график должен обновляться не позднее чем через 100 мс.
- **Rationale:** Плавная работа с ползунками.
- **Acceptance Criteria:** Задержка между изменением ползунка и обновлением графика не превышает 100 мс.
- **Verification Method:** Test

**REQ-PERF-003 — Скорость экспорта**
- **Statement:** Экспорт звука длительностью 5 секунд в WAV должен выполняться не более чем за 500 мс.
- **Rationale:** Быстрое сохранение.
- **Acceptance Criteria:** Время от нажатия кнопки до появления файла не превышает 500 мс.
- **Verification Method:** Test

#### 3.3.2 Безопасность

**REQ-SEC-001 — Отсутствие внешних запросов**
- **Statement:** Приложение не должно отправлять данные пользователя во внешние сети.
- **Rationale:** Параметры и звуки — собственность автора.
- **Acceptance Criteria:** Политика CSP запрещает внешние соединения; в панели сети нет запросов при работе.
- **Verification Method:** Inspection

**REQ-SEC-002 — Проверка файла параметров**
- **Statement:** Система должна проверять загружаемый JSON: размер не более 64 КБ, типы и диапазоны значений, отсутствие неизвестных полей.
- **Rationale:** Защита от некорректных и вредоносных файлов.
- **Acceptance Criteria:** Файлы 100 КБ, со строкой вместо числа и с лишними полями отклоняются с сообщением.
- **Verification Method:** Test

#### 3.3.3 Надёжность

**REQ-REL-001 — Некорректные данные**
- **Statement:** Некорректные параметры и файлы не должны приводить к аварийному завершению приложения.
- **Rationale:** Файлы приходят от разных источников.
- **Acceptance Criteria:** Для 10 негативных файлов выводится сообщение, приложение работает.
- **Verification Method:** Test

**REQ-REL-002 — Автозапуск звука**
- **Statement:** Если браузер блокирует воспроизведение до действия пользователя, система должна возобновить звук после первого клика без потери параметров.
- **Rationale:** Политика автозапуска браузеров.
- **Acceptance Criteria:** После блокировки первое нажатие «Play» воспроизводит звук.
- **Verification Method:** Test

**REQ-REL-003 — Безопасная громкость**
- **Statement:** Громкость при запуске приложения и при загрузке пресета не должна превышать 50 %.
- **Rationale:** Защита слуха и динамиков.
- **Acceptance Criteria:** После загрузки приложения и пресета громкость не выше 50 %.
- **Verification Method:** Test

#### 3.3.4 Доступность

Отдельных требований нет: приложение работает локально в браузере пользователя и не зависит от доступности серверов.

#### 3.3.5 Наблюдаемость

**REQ-OBS-001 — Журнал ошибок**
- **Statement:** Приложение должно записывать в консоль ошибки и предупреждения с кодом, уровнем и описанием.
- **Rationale:** Диагностика проблем.
- **Acceptance Criteria:** Для ошибок REQ-FUNC-020 и REQ-REL-002 в консоли есть записи с кодом.
- **Verification Method:** Inspection

### 3.4 Соответствие стандартам

**REQ-COMP-001 — Формат WAV**
- **Statement:** Файл WAV должен соответствовать спецификации RIFF/WAVE (PCM, формат 1) с корректными полями размеров.
- **Rationale:** Совместимость с движками.
- **Acceptance Criteria:** Файл успешно проверяется утилитой анализа и читается в трёх сторонних программах.
- **Verification Method:** Test

**REQ-COMP-002 — Доступность интерфейса**
- **Statement:** Контраст текста и фона элементов управления должен быть не менее 4.5:1 (WCAG 2.1, критерий 1.4.3), ползунки доступны с клавиатуры.
- **Rationale:** Читаемость и доступность.
- **Acceptance Criteria:** Проверка инструментом аудита не выявляет нарушений; ползунки управляются стрелками.
- **Verification Method:** Inspection

**REQ-COMP-003 — Формат параметров**
- **Statement:** Файл параметров должен быть корректным JSON (RFC 8259, UTF-8) с полем `schemaVersion`.
- **Rationale:** Совместимость и расширяемость.
- **Acceptance Criteria:** Файл разбирается стандартным парсером; поле версии присутствует.
- **Verification Method:** Test

### 3.5 Проектирование и реализация

#### 3.5.1 Установка

Установка не требуется: приложение открывается в браузере из статической сборки (`index.html`) или с локального сервера разработки.

#### 3.5.2 Сборка и поставка

Сборка выполняется командой `npm run build`; результат — каталог статических файлов без серверной части.

#### 3.5.3 Распределение

Исходный код хранится в Git-репозитории; ветка с документами и ветка с кодом разделены, изменения вносятся через pull-request.

#### 3.5.4 Сопровождаемость

**REQ-MAINT-001 — Тестовое покрытие**
- **Statement:** Модульные тесты должны покрывать не менее 80 % строк ядра (синтезатор, эффекты, WAV, формат параметров).
- **Rationale:** Безопасные изменения.
- **Acceptance Criteria:** Отчёт покрытия показывает не менее 80 %.
- **Verification Method:** Analysis

**REQ-MAINT-002 — Независимость ядра**
- **Statement:** Ядро синтеза не должно использовать DOM и Web Audio API; оно получает параметры и возвращает массив отсчётов.
- **Rationale:** Тесты без браузера.
- **Acceptance Criteria:** Каталог `core/` не содержит браузерных API; тесты запускаются в Node.js.
- **Verification Method:** Inspection

#### 3.5.5 Повторное использование

**REQ-REUSE-001 — Ядро как библиотека**
- **Statement:** Ядро синтеза должно быть оформлено как независимый пакет, пригодный для использования в игре (генерация звуков во время работы).
- **Rationale:** Повторное использование в проектах Заказчика.
- **Acceptance Criteria:** Пример использования ядра вне интерфейса работает в Node.js.
- **Verification Method:** Demonstration

**REQ-REUSE-002 — Версионирование параметров**
- **Statement:** Формат параметров должен содержать версию схемы; загрузка файлов старых версий должна поддерживаться миграцией.
- **Rationale:** Совместимость сохранённых звуков.
- **Acceptance Criteria:** Файл версии 1 корректно загружается в версии 2 после миграции.
- **Verification Method:** Test

#### 3.5.6 Переносимость

**REQ-PORT-001 — Операционные системы**
- **Statement:** Приложение должно работать в поддерживаемых браузерах на Windows, macOS и Linux.
- **Rationale:** Разные компьютеры разработчиков.
- **Acceptance Criteria:** Сценарии C-1…C-6 выполнены на трёх системах.
- **Verification Method:** Demonstration

#### 3.5.7 Стоимость

Проект учебный: платные сервисы и лицензии не используются, все зависимости имеют открытые лицензии.

#### 3.5.8 Сроки

Срок определяется графиком дисциплины; итерации приведены в разделе 2.6.

#### 3.5.9 Доказательство концепции

**REQ-POC-001 — Прототип**
- **Statement:** На первой итерации должен быть создан прототип: прямоугольная волна, огибающая ADSR, воспроизведение и экспорт в WAV.
- **Rationale:** Проверка основных технических рисков (синтез, формат WAV).
- **Acceptance Criteria:** Прототип демонстрируется преподавателю: созданный WAV открывается в аудиоредакторе и звучит так же.
- **Verification Method:** Demonstration

#### 3.5.10 Управление изменениями

Изменения требований оформляются новой версией SRS и записью в таблице «История изменений». Замечания Заказчика и преподавателя вносятся через pull-request; отклонённые замечания сопровождаются обоснованием.

### 3.6 ИИ/МО

Методы искусственного интеллекта и машинного обучения в продукте не используются.
